# INSIGHT Risk – Customer Question List

## Purpose

This document provides a practical list of customer-facing questions for prototype evaluation sessions.

The questions are designed to help evaluate:

- clarity of communication
- threshold interpretation
- workflow fit
- preference across prototype formats
- perceived risk of misinterpretation

These questions can be used in:

- conference booth testing
- customer interviews
- advisory board sessions
- workflow review discussions

---

## Recommended Core Questions

### 1. First impression

- What is your first impression of this result?
- What do you think this result is trying to communicate?
- Is the meaning clear at first glance?

### 2. Ease of understanding

- How easy is this result to understand?
- Which part is easiest to understand?
- Which part, if any, feels confusing?

### 3. Risk interpretation

- Based on what you see, how would you interpret this patient’s risk?
- Does this feel like a risk communication tool, or more like a triage alert?
- Does the current wording feel appropriately neutral?

### 4. Threshold understanding

- Is the threshold logic clear?
- If more than one threshold is shown, is that helpful or confusing?
- Would you prefer to see a single threshold or multiple thresholds?

### 5. Prototype preference

- Which format do you prefer overall?
- Which version would you trust the most?
- Which version would be easiest to use in practice?
- Which version would you be least likely to use, and why?

### 6. Workflow fit

- Where in your workflow would you expect to see this information?
- Would this fit better in a compact card, a detailed panel, or a report section?
- Which prototype would fit best in your EMR, RIS, or PACS environment?

### 7. Actionability and safety

- Does any version feel like it could be over-interpreted?
- Does any version feel too simplified?
- Does any version feel like it is suggesting action too strongly?

### 8. Closing feedback

- If you could change one thing, what would it be?
- What additional information, if any, would you want to see?
- Would you feel comfortable using this format in routine practice?

---

## Questions By Evaluation Goal

## A. If the goal is to compare simple vs complex presentation

- Do you prefer the simpler single-threshold version or the more detailed version?
- At what point does added information become too much?
- Which version best balances clarity and completeness?

## B. If the goal is to evaluate multiple-threshold display

- Does showing both thresholds help you understand the result better?
- Does dual-threshold display increase trust, or create confusion?
- Would you want both thresholds shown all the time, or only in certain cases?

## C. If the goal is to evaluate Prototype 2 configurability

- If you could choose one interpretation mode, which would you choose: `1.7%`, `3.0%`, or `Both`?
- Does allowing the threshold mode to change feel useful or unstable?
- Should this be site-configurable, user-configurable, or fixed?

## D. If the goal is to evaluate visual presentation

- Does the visual scale make the result easier to understand?
- Does the scale help with borderline cases?
- Is the visual presentation worth the extra screen space?

---

## Questions By Prototype

## Prototype 1

- Is the fixed `3.0%` threshold easy to understand?
- Does this feel clear enough for real workflow use?
- Does this version feel too simplified?

## Prototype 2

- Which cutoff mode feels most appropriate: `1.7%`, `3.0%`, or `Both`?
- Does configurability make this more useful or more confusing?
- Would you want your institution to choose one mode and keep it fixed?

## Prototype 3

- Does showing both threshold interpretations help or distract you?
- Would this version improve transparency?
- Is this too much information for routine use?

## Prototype 4

- Is this version easier to understand because it is visual?
- Does the visual scale help you interpret borderline cases more quickly?
- Would this fit in your actual system layout?

---

## Suggested Short Question Set

Use this when time is limited.

- Which version is easiest to understand?
- Which version would fit best in your workflow?
- Is showing both thresholds helpful or confusing?
- Which version would you choose for real use?
- What would you change?

---

## Suggested Extended Question Set

Use this for deeper interviews.

- What do you think this result means?
- How easy is this result to understand?
- Does the threshold logic feel clear?
- Does the wording feel neutral and appropriate?
- Which prototype do you prefer?
- Which prototype feels safest from a misinterpretation perspective?
- Which prototype feels most realistic for EMR or RIS integration?
- Would you want one threshold, two thresholds, or a configurable approach?
- Does the visual version improve understanding?
- What would you change before real deployment?

---

## Rating-Scale Question Options

These can be used in a survey form.

- How easy was this result to understand? `1–5`
- How clinically useful does this format feel? `1–5`
- How confusing is the threshold logic? `1–5`
- How well would this fit your workflow? `1–5`
- How likely would you be to use this format if deployed? `1–5`

---

## Moderator Reminders

- Start with open-ended questions before introducing interpretation
- Avoid leading the customer toward one prototype
- Ask why, not only which
- Capture exact wording when the customer describes confusion or trust
- Focus on communication quality rather than forcing a threshold decision
